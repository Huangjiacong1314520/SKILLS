# 搜索与数据库接力

只在方向需要校准、材料池不足或出现具体证据缺口时读取本文件。目标是让真实返回材料修正问题和检索，不是一次写出“完美检索式”。

## 1. 对齐检索入口

并排记录三项：

| 项目 | 必须回答 |
| --- | --- |
| 当前任务 | 本轮材料要支持哪个决定或输出？ |
| 概念关系 | 哪些是核心对象、条件、作用或结果？哪些不能当同义词合并？ |
| 真实结果 | 实际进入了什么、漏掉了什么、误检为何出现？ |

研究者确认任务与不可丢失的概念轴；Agent 拆分概念、扩展表达、测试删除与增加限制，并解释实际偏差。若结果动摇了问题形成链中的前提，暂停并让研究者确认是否改写问题。

## 2. 在钓鱼与鲸吞之间往返

### 钓鱼法

围绕当前最具体的信息缺口，用已有表达执行一次搜索，再依据无结果、误检、新术语和相邻对象调整下一轮。适合：

- 陌生方向中取得基本名词和检索支点；
- 检查候选是否高度重复；
- 寻找参数、方法细节、代码或直接证据；
- 用实践或分析暴露的新问题补洞。

局部搜索或 Agent 回答只提供线索，不能代表领域全貌。

### 鲸吞法

当需要观察版图或防止局部结果以偏概全时，扩大材料范围，允许有限冗余，把可能有参考价值的材料先纳入宽泛池；后续再通过分组和核心池筛选真正需要阅读的部分。不要为了扩大数量引入当前无法处理的大量无关材料。

二者没有固定先后。缺术语时先钓鱼，需要判断版图时鲸吞，问题具体后再钓鱼。材料足以启动下一步就暂停。

## 3. 保存真实结果回流

每轮至少保存：

- 轮次、日期和执行者；
- 实际数据库或搜索载体；
- 实际执行的检索式与过滤条件；
- 返回数量和检查的结果范围；
- 代表性相关、误检和疑似遗漏记录；
- Agent 对偏差的解释；
- 下一轮建议及其“尚未执行”状态；
- 本轮是否改变任务、概念或纳入边界。

不得把建议检索式写成已执行结果，不得用“未找到”直接推导“不存在”。

## 4. 数据库接力检索—检索回传包

当 Agent 不能直接访问目标数据库时，先输出一份可执行接力包：

1. **检索目的**：本轮要支持的决定和停止条件；
2. **概念检索式**：概念块、同义表达、必须保留和可测试删除的项；
3. **数据库语法版**：针对用户实际数据库翻译的候选语句，明确标为“建议，未执行”；
4. **执行设置**：字段、时间范围、文献类型、语言、排序、去重前后要求；
5. **试搜检查**：先回传一组能暴露相关、误检与遗漏的代表性结果；
6. **收获要求**：试搜通过后导出完整结果所需字段。

用户回传至少包含：

- 数据库或平台、执行日期；
- 实际执行的完整检索式；
- 实际过滤和排序条件；
- 总结果数；
- 试搜代表记录，含标题、摘要、关键词、年份和稳定标识；
- 通过试搜后得到的完整导出或可访问位置；
- 用户观察到的相关、误检、遗漏或希望保留的信号。

试搜用来校准检索式，完整导出用来建立材料池。两者不能互相冒充。

## 5. 宽泛池和停止条件

宽泛池记录来源、检索轮次、纳入原因和当前处理状态。它支持元数据趋势、相关性和方向选择；没有逐篇分析时不得声称掌握全部研究内容。

满足以下条件即可停止本轮搜索：

- 当前决定所需的主要概念和相邻表达已经出现；
- 代表性相关结果进入池中，主要误检原因已知；
- 尚存遗漏风险已记录，不会被写成“查全”；
- 新增材料不再显著改变当前方向，或下一步行动本身能提供更便宜的反馈。

下一步不落地、关键证据缺失或新结果改变前提时，再返回搜索并增量更新。
