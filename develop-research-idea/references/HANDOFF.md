# 选定后的深化与交接

只在研究者已经选定一个候选后读取本文件。目标是形成有来源支撑的初步研究方案和 `选题交接包`，并把“选题形成”与“0→1 验证”清楚分开。

## 1. 回到完整材料池

以选定候选为新的输出目标，重新检查宽泛池、核心池、逐篇记录、阶段报告和少数信号：

1. 明确候选依赖的关键论断、假设和现实条件；
2. 从完整池中定向筛选被前一轮忽略但高度相关的材料；
3. 对每篇新增或重审材料标记支持、反驳、限定或扩展；
4. 暴露新的理论、方法、变量、群体、边界条件和冲突；
5. 只有出现具体缺口时补搜，仍保存真实结果回流；
6. 根据证据修订研究问题、可能机制、方法轮廓和贡献表述，同时保留修改前版本和理由。

不要直接输出一份覆盖异议的“进化版方案”。深化过程必须让研究者看见新增证据怎样改变候选。

## 2. 关键论断的全文门

至少把以下会承担交接结论的论断回到全文核查并定位：

- 基线或现有方法真正缺少什么；
- 候选与最相近工作的实质差异；
- 可能机制或因果链依赖的直接证据；
- 方法路线成立所需的关键条件、资源和边界；
- 主要冲突证据与作者明确局限。

题录只能支持元数据，摘要只能记录作者摘要中的声明。只有摘要的线索可进入“待核查”，不能成为上述关键论断的唯一支撑。

## 3. 选题交接包字段

从 [`../assets/research-idea-handoff.md`](../assets/research-idea-handoff.md) 复制模板，并填写：

- 选定候选原话、选择理由和保留异议；
- 研究对象与情境、研究问题；
- 基线与痛点、拟议改变；
- 可能机制或因果链、预期可观察结果；
- 问题假设与方案假设；
- 初步方法轮廓与关键对照；
- 可用数据、代码、设备、时间、人员和其他现实条件；
- 关键来源、定位、证据深度及其支持关系；
- 冲突证据、限制、替代解释；
- 按优先级排列的致命不确定性；
- 明确未知项和仍未覆盖的范围。

作者声明、Agent 推断、研究者决定和真实结果分别标记。未知项写“未知”，不填充成貌似完整的研究计划。

## 4. 交接门

只有同时满足以下条件，才能把状态改为“选题形成完成，尚未验证”：

- 研究者已选定并确认候选；
- 主视角提案与候选对照审查均保留；
- 完整文献池已经过定向复查和必要深化；
- 关键论断已由全文定位支持；
- 模板字段均有内容或明确未知；
- 现实约束、致命不确定性、冲突证据、限制和未覆盖范围可见；
- 研究者确认交接包准确。

通过交接门不代表文献已经查全、创新成立、机制正确或方法可行。它只说明候选已被加工成后续验证可以接手的草案。

## 5. 下游边界

结束时提醒研究者自行调用 `$validate-research-idea`。下游将交接包映射为可验创新点卡，只追问会改变验证路径的缺失信息，再寻找致命不确定性的最短验证路径。

不要在本 Skill 中自动启动验证、创建验证档案、宣布 Go/No-Go，或把初步方法轮廓扩写成完整开题报告。
