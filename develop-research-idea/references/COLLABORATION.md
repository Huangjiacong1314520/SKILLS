# 协作与依赖

本文件只在检查依赖、出现长期领域决定，或需要选择 Matt 工作流分支时读取。这里的规则属于 Agent 工程适配，不声称来自“搜聚分”原文或训练营。

## 1. 依赖层级

| 层级 | Skills | 处理 |
| --- | --- | --- |
| 核心 | `grilling`, `domain-modeling` | 启动时检查；缺失即提醒安装并停止 |
| 推荐 | `grill-with-docs` | 建议安装；它是用户调用型包装器，本 Skill 不自动调用 |
| 条件 | `research`, `wayfinder`, `handoff` | 分支真正需要时再检查并提醒，不阻塞普通启动 |
| 下游 | `validate-research-idea` | 缺失不影响完成交接包，但必须说明后续验证入口不存在 |

核心依赖缺失时直接回复：

```text
本 Skill 依赖 Matt 的 grilling 与 domain-modeling 来保持“一次一个决定”和长期领域记录，当前环境缺少其中至少一个。请先运行：

npx skills@latest add mattpocock/skills

安装时至少选择 grilling、domain-modeling；建议同时安装 grill-with-docs、research、wayfinder、handoff。安装完成后，请重新调用 $develop-research-idea。
```

不要在核心依赖缺失时假装已经调用它们，也不要为了继续而取消研究者决策权。

## 2. 默认协作内核

- 使用 `grilling` 处理会改变方向、边界、评价标准或路线的决定；一次只问一个，给推荐和理由。
- 能从用户材料、仓库和可信来源查到的事实由 Agent 先查，避免把可查事实变成用户问卷。
- 研究者决定值得解决什么、什么结果有意义、愿意承担什么主张，以及兴趣和现实约束如何取舍。
- Agent 承担可规模化、可追溯、可逆的信息处理：检索迭代、逐篇记录、批次比较、来源追踪和一致性检查。
- 阶段报告讨论可以自由展开；一旦出现多个待决定分支，先排序，再逐个进入 `grilling`。

三个固定决策门只标记方向或任务确认、候选选择和交接确认，不限制其他沟通。

## 3. 何时使用 domain-modeling

当讨论形成会长期复用的术语、研究边界、成功含义或领域决定时，调用 `domain-modeling` 并遵循当前项目的 domain docs 配置及时更新。以下内容不写入领域文档：

- 当前批次进度；
- 等待回传；
- 临时候选排序；
- 本轮检索式；
- 尚未确认的 Agent 推断。

这些运行状态留在 `STATUS.md` 或对应研究工件中。若用户希望用 `$grill-with-docs` 统一完成深度追问和文档更新，提醒其自行调用；本 Skill 不能自动调用另一个用户调用型 Skill。

## 4. 条件分支

### research

只在需要针对规范、方法、数据或技术事实开展独立的一手来源研究时调用。它补充可核查事实，不替研究者选择课题价值，也不替代核心文献池逐篇分析。

### wayfinder

当工作跨多个会话、存在多个阻塞依赖或仍有大片不能精确出票的迷雾时，建议研究者自行调用 `$wayfinder`。交接时提供 destination、已有工件、当前 frontier 和 fog；不要把普通多批文献分析自动升级成大型项目。

### handoff

当研究者需要把当前对话交给另一任务或 Agent 时，建议其自行调用 `$handoff`。Matt 的 handoff 是会话桥，不等同于本 Skill 的领域工件 `research-idea-handoff.md`；前者应引用后者，不复制其全部内容。

### prototype

选题形成通常不需要抛弃式软件原型。只有某个研究想法本身依赖界面或业务逻辑设计问题，且用户明确希望先观察原型时，才建议单独使用；科学命题的 0→1 原型属于下游验证。

## 5. 状态与资产生命周期

- 用明确目的地和唯一阻塞前沿控制当前工作，不让所有未知同时展开。
- 每类事实只维护一个权威位置；`STATUS.md` 只做索引和恢复入口。
- 已决定、未知、等待回传和明确不在范围内分开。
- 阶段产物是长期可追溯资产；临时搜索尝试和批次运行状态是短期状态。
- 新证据造成路线冲突时退回建议模式，由研究者重新决定；工作量大不等于可以扩大 Agent 的价值判断权限。

这些原则借鉴 Matt Skills 的协作纪律和工程资产思想，并针对科研选题的证据、文献与人工判断作了适配。
