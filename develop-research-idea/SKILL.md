# 发展研究构想

## 目标与边界

把真实检索结果转化为有来源、可比较、可继续验证的研究候选组合。

正常终点是：

- 持久化的中文研究工作区；
- 分层的研究候选卡；
- 每个候选的证据链、重复风险、贡献理由、证据缺口与最低验证提示；
- 等待用户选择继续深化的候选。

把完整 0→1 验证、最终选题决策、完整实验方案和开题报告留给后续流程。候选阶段只有在直接方法证据充分时才展开技术路线；否则标为“待强相关检索后深化”。

## 核心契约

1. **真实检索由用户执行。** 设计可执行检索式、排序、抽样和导出要求；把用户返回的真实记录作为发现证据。可以阅读用户提供的文件、全文和明确链接，但不代替用户访问数据库或搜索引擎。
2. **生成检索式不等于完成检索。** 没有真实记录时，只能形成`检索假设`和检索交接包。
3. **一个任务只有一个主证据池。** 新结果去重后增量入池；批次、主题组和强相关集合都是派生视图。
4. **来源事实与 Agent 推论分开。** 所有关键判断都能回溯到稳定文献编号和证据位置。
5. **新颖性是有范围的检索结论。** 使用“在已声明的数据库、检索式和时间范围内暂未发现直接先例”；把重复风险与贡献价值分开判断。
6. **质量决定数量。** 以证据充分性停止，不为达到固定篇数或候选数而凑数。

## 启动或恢复

1. 在当前研究项目中寻找`研究构想工作区/研究简报.md`。
2. 如果工作区存在，先完整读取`研究简报.md`、`检索日志.md`及其中标记的当前状态，再读取本轮相关文件；保持原有`RE###`编号并从暂停点继续。
3. 如果工作区不存在，运行：

   ```text
   python <skill目录>/scripts/初始化研究工作区.py --path <项目目录>/研究构想工作区
   ```

4. 每次启动都完整读取[方法与执行路由.md](references/方法与执行路由.md)，据此诊断起点并选择内部动作。不要让用户手动选择“侦察、聚焦或续研”。
5. 只有缺失信息会实质改变路线时，才询问用户；其余诊断写入`研究简报.md`后继续。

当`2.1`起点覆盖多个差异很大的子领域，且没有导师方向、可用方法、资源或锚点约束时，选择子领域本身就是实质改向：先询问一个最能缩小边界的问题。用户无法提供边界时，只设计不承诺具体子领域的领域级侦察，不任意指定一个熟悉方向。

## 执行循环

### 1. 诊断起点

同时记录：

- 认知颗粒度：`2.1`完全没有概念、`2.2`知道大方向、`2.3`了解细分方向但无法推进；
- 起始信号：好奇、现实问题或需求、异常或失败结果、文献关系；
- 证据资产：无可靠材料、具体问题或异常、文献池、锚点论文、已有候选；
- 用户目标与约束：时间、技能、设备、数据、代码、课题组积累和成果目标。

所有实质性研究边界都必须来自用户输入、已有证据或真实检索反馈；把临时假设明确标为待检索检验，不把 Agent 熟悉度当作选向依据。

完成标准：`研究简报.md`中足以解释为什么选择当前执行路由。

### 2. 设计并交接检索

需要检索时，完整读取[检索设计与交接.md](references/检索设计与交接.md)。自动组合鲸吞和钓鱼动作：

- 需要版图和关系多样性时使用鲸吞；
- 需要术语、具体问题、异常原因、方法细节、证据缺口或重复核查时使用钓鱼；
- 术语不清时先钓鱼学习表达，再构造鲸吞检索；
- 关系分析暴露缺口后，再用钓鱼补查并增量回池。

数据库批量检索先交接小样本相关度测试，再交接完整导出。把检索目标、数据库、完整检索式、排序方式、返回字段和本轮判定问题写入`检索日志.md`，然后暂停等待用户结果。

完成标准：用户拿到一份可以直接执行且返回要求明确的检索交接包；在真实结果返回前，候选状态保持为`检索假设`。

### 3. 入池与证据分层

收到检索结果或已有文献库时，完整读取[证据池与来源记录.md](references/证据池与来源记录.md)。先审计已有材料，再增量导入；不要推倒重建。

对于 CSV 或 TSV，可运行：

```text
python <skill目录>/scripts/导入文献来源.py --workspace <工作区> --input <导出文件> --database <数据库> --query-id <检索轮次>
```

对每篇记录标记当前可用证据层级：`题录`、`摘要`或`全文`。把作者明确报告的事实、数据和局限写入`证据笔记.md`；把分析和推论写入相应的 Agent 分析字段。

完成标准：本轮每条纳入记录都有稳定编号、可追溯来源、证据层级和纳入理由；重复记录没有获得新编号。

### 4. 分析关系

完整读取[关系分析视角.md](references/关系分析视角.md)。根据当前起点选择有用的分析视角，不机械遍历所有视角。

每条关系记录必须说明：

- 涉及哪些文献或现实证据；
- 各来源明确报告了什么；
- Agent 识别出什么关系；
- 该关系怎样导出候选；
- 哪些仍是推论；
- 缺少什么证据。

完成标准：每个准备进入候选卡的想法都能回溯到一条完整关系记录。

### 5. 形成并升级候选

完整读取[研究候选卡.md](references/研究候选卡.md)。按证据状态管理候选：

- `检索假设`：只有问题表达、关系猜想或检索计划；
- `初步候选`：已经绑定真实记录和来源事实；
- `证据化候选`：关键关系、价值和重复风险已经过针对性检索，决定性方法、结果或局限已核查到相应全文位置。

候选升级前执行重复风险检索交接。发现近似或实质相同工作时，将其增量入池，比较问题、机制、方法、条件和预期贡献，然后改写、降级或提交用户决定。

完成标准：每张候选卡字段完整；证据状态与实际材料一致；事实、关系和推论没有混写。

### 6. 比较并交付候选组合

先按证据状态分层，再给出多维候选画像：证据成熟度、潜在贡献、重复风险、实施可行性、关键不确定性、最低验证成本和目标匹配度。使用适合各维度的状态和文字理由，不合成为统一总分。

用户目标明确时，说明哪些候选更匹配该目标；目标不明确时，展示画像而不宣布绝对最佳。高潜力但证据较弱的想法可以进入“探索性候选”，但其潜力不能替代证据状态。

完成标准：用户能够据此选择下一步候选；每个候选都有下一轮检索建议或最低验证提示；流程在完整“验”之前停止。

## 暂停规则

只在以下情况暂停：

- 缺少会改变路线的用户目标或现实约束；
- 等待用户执行外部检索或提供全文；
- 候选组合完成，等待用户选择；
- 新证据要求实质改变用户指定方向，例如发现相同工作、核心假设被直接反证或关键资源明显不匹配。

去重、编号、证据分层、关系分析、候选卡更新和工作区维护在材料充足时连续完成。

## 工作区维护与校验

完整读取[工作区规范.md](references/工作区规范.md)后再改变工作区结构。所有面向用户的文件名、标题和字段默认使用中文。

每轮结束前运行：

```text
python <skill目录>/scripts/校验研究工作区.py --workspace <工作区>
```

更新`研究简报.md`中的当前阶段、已完成工作、暂停原因、下一项输入和下一步动作。保留历史记录，执行增量更新，不用重新生成覆盖历史。
