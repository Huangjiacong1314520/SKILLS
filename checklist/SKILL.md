# Checklist

这是一次 **audit**，不是普通润色。它检查作者意图能否被读者重建、论证是否自洽、结论是否有证据闭环，以及稿件是否符合目标期刊规范。

## 必读规则

开始任何审查前，完整读取 [`GUIDE.md`](GUIDE.md) 至 EOF；无法读取就停止，不得凭记忆声称覆盖清单。只有追溯覆盖关系时才读 [`COVERAGE.md`](COVERAGE.md)，只有某个案例的文字解释仍不足以判断时才读取 `references/source/` 中对应原文及其图片。

## 第一次调用：冻结读者贡献

当当前对话中还没有冻结的“读者重建贡献”时：

1. 只依据用户提供的手稿，重建研究对象、研究问题、方法、关键结果和相对贡献。
2. 用一句话或一个短语给出核心贡献；若存在多个竞争版本，逐一列出，不替作者合并。
3. 标出读者从哪些段落或图表得到该理解，以及最早在何处能够确定论文要做什么。
4. 将结果明确标记为“已冻结的读者重建贡献”，此后不得因作者解释而回改。
5. 停止审查，强制要求用户另行提供“我想表达的贡献”。提示用户用 `/checklist 我想表达的贡献：...` 继续。

如果用户在第一次调用时已经给出作者贡献声明，仍先完成并冻结读者重建结果，不在本轮比较；同时注明独立判断可能已受提示影响。

完成条件：冻结结果已输出，且本轮没有继续进入全文问题清单。

## 后续调用：对照并全量审查

仅当对话中同时存在冻结结果和作者贡献声明时继续：

1. 对照两者，判断为一致、部分偏移、多重贡献竞争或手稿未传达作者意图；引用手稿位置说明差异。
2. 按 `GUIDE.md` 的依赖顺序应用所有适用规则。即使上游错误严重，也不得停止后续覆盖。
3. 先做手稿审查；用户提供文献、原始图表、期刊指南或证据包时再做证据审查。缺少材料的规则标记为“证据不足，无法判断”。
4. 对每个发现使用且只使用以下状态：确认错误、待核验疑点、证据不足无法判断、已核查当前未发现问题。
5. 审查优先、改写受控：语言层面可给候选改写；涉及贡献、因果、数据解释或引用内容时，只给修改方向或追问，不补造科学含义和证据。

## 报告格式

依次输出：

1. 当前材料与审查边界
2. 冻结的读者重建贡献
3. 作者贡献声明及两者差异
4. 按依赖排序的修订路线
5. 逐项发现：位置、规则编号、证据状态、原文证据、判断思想、修改方向、仍需材料
6. 覆盖摘要：每个规则编号均有状态；“已核查当前未发现问题”只在摘要中列出

不要给论文总分，不增加严重程度等级，不把无法核验写成通过。

完成条件：`GUIDE.md` 的每个规则均被标为适用并给出状态，或明确说明不适用；所有未检查内容都有原因；所有发现都有可复查位置；没有疑点被写成确认错误。
