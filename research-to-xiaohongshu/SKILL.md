# 把科研内容转化为小红书笔记

## 目标与边界

把已有科研资产转化为平台原生、可信、可搜索、可收藏、可持续连载的内容。

正常交付物是：

- 一张选题角度卡；
- 一组标题与封面文案候选；
- 一套多图笔记脚本；
- 一版发布正文、话题与互动设计；
- 一份事实核查、泄密与平台风险检查；
- 在已有发布数据时，一条明确的下一轮内容实验。

本 Skill 优化的是内容被看见和被留下的概率，不承诺“爆款”、固定播放量或粉丝增长。不能用伪造经历、夸大科研结果、虚构论文或无关热词换流量。

## 必读与按需读取

开始前完整读取 [`references/content-patterns.md`](references/content-patterns.md)。

需要生成完整笔记包时，读取并使用 [`assets/post-package.md`](assets/post-package.md)。

用户要求模仿某位博主时，优先读取用户提供的主页截图、笔记截图、标题列表或公开链接。只能抽象其结构、节奏、选题和视觉规律，不复制其独特措辞、故事、身份表达或整篇内容。

用户要求依据发布结果复盘时，读取同一账号已有的选题表、发布记录和可用后台指标；没有数据时，不把主观判断伪装成平台结论。

## 核心契约

1. **真实材料先于文案。** 先确认哪些内容来自论文、实验、仓库、笔记或真实经历，再进行传播表达。无法核验的内容标为观点、假设或待确认。
2. **用户问题先于仓库功能。** 不从“我做了一个 Skill”开始，而从目标读者正在经历的卡点、错误、损失或愿望开始；Skill 是解决方案和证据，不是天然选题。
3. **一篇笔记只承诺一个主要结果。** 封面、标题、正文和图片围绕同一问题，不把检索、选题、实验、写作和投稿全部塞进一篇。
4. **平台表达不等于降低准确性。** 可以口语化、制造对比和悬念，但不能删除会改变结论的前提、适用范围和失败条件。
5. **真人感来自具体过程。** 优先使用真实动作、失败、修改、截图、对比和决策理由，不用空泛情绪、万能口号或批量化 AI 套话冒充个人表达。
6. **每篇只设一个主行为目标。** 在点击、完读、收藏、评论、关注、搜索发现中选择一个主目标，其他目标作为次要结果。
7. **增长依靠系列和实验。** 不根据单篇表现宣布账号定位成功或失败；保留选题、标题、封面、结构和结果的迭代记录。
8. **不复制，不伪装。** 模仿的是内容机制，不是假冒他人身份、搬运他人笔记或洗稿。

## 启动输入

优先从当前上下文、项目文件或用户提供材料中确定：

- 内容源：论文、读书笔记、实验、代码、Skill、踩坑记录、观点或科研日常；
- 目标读者：本科生、硕士生、博士生、青年教师、科研工程师或某个具体学科群体；
- 主要目标：点击、收藏、评论、关注、搜索发现或仓库认知；
- 证据资产：截图、步骤、前后对比、数据、代码提交、失败记录、文献来源；
- 账号阶段：未发布、冷启动、已有稳定栏目或正在复盘；
- 保密边界：未发表结果、合作方信息、学生隐私、单位要求和版权限制。

能可靠推断时直接继续。只有缺失信息会实质改变目标读者、泄密边界或内容路线时，才问一个澄清问题。

完成标准：能够用一句话写出“给谁看、解决什么、凭什么可信、希望读者做什么”。

## 执行循环

### 1. 审计内容源

从材料中提取六类可传播单元：

- **卡点：** 读者正在经历的具体困难；
- **误区：** 常见但无效、危险或代价高的做法；
- **转折：** 用户何时发现原思路不够；
- **方法：** 可以复现的动作、判断或工作流；
- **证据：** 截图、结果、代码、前后对比、来源或真实复盘；
- **边界：** 方法不适用的情况、尚未解决的问题和保密限制。

不要把只有功能名、抽象理念或技术术语的材料直接当成选题。

完成标准：至少找到一个真实卡点和一种可信证据；没有证据时，只能做观点、讨论或过程记录型笔记。

### 2. 选择内容类型

根据材料与目标选择一种主类型：

1. **痛点诊断型：** 解释“为什么你一直卡住”，主目标通常是点击和评论；
2. **方法教程型：** 给出可执行步骤、清单或模板，主目标通常是收藏和搜索；
3. **失败复盘型：** 展示错误、修正和教训，主目标通常是信任和关注；
4. **工具或 Skill 实测型：** 用真实任务展示工具价值，主目标通常是收藏和仓库认知；
5. **观点反差型：** 对常见科研建议给出有证据的修正，主目标通常是评论和分享；
6. **构建公开型：** 持续记录一个科研工作流或 Skill 如何被设计、验证和修改，主目标通常是关注；
7. **科研事件解释型：** 借当前学术事件解释机制、规则或争议，主目标通常是点击和评论。

一篇笔记只能有一个主类型。素材很多时拆成系列。

完成标准：选题角度卡中写明主类型、主目标、目标读者、单一承诺、证据和风险。

### 3. 判断传播潜力

从以下维度给出“强、中、弱”和一句理由，不合成神秘总分：

- 需求广度：多少目标读者遇到这个问题；
- 痛点强度：问题是否造成时间、焦虑、返工或结果损失；
- 结果具体性：读者能否快速理解看完得到什么；
- 新信息量：是否超出常见泛泛建议；
- 证据强度：是否有真实过程、截图、对比或来源；
- 收藏价值：是否能形成步骤、表格、判断框架或模板；
- 讨论空间：是否存在真实分歧或可回答的问题；
- 搜索价值：标题和正文是否对应长期会被搜索的明确问题；
- 账号一致性：是否能自然接入已有系列和专业身份。

传播潜力弱时，优先换角度、缩小承诺、补证据或拆分内容，而不是用更夸张的标题掩盖问题。

### 4. 设计标题与封面

标题至少生成 8 个候选，分为四组：

- 搜索型：包含目标问题和核心关键词；
- 痛点型：明确读者、卡点和损失；
- 反差型：呈现常见做法与真实结论的冲突；
- 故事型：呈现一次失败、转折或实测结果。

标题优先包含“目标人群 + 具体问题 + 结果或反差”，但不机械套公式。

封面文案生成 3 个候选。默认只表达一个信息层级，控制在手机首屏可迅速识别的长度；技术术语过长时用读者语言改写，把精确定义放在内页。

不要默认使用“震惊”“封神”“保姆级”“建议所有人”“偷偷在用”“一篇顶刊”等夸张词。只有用户明确要求特定风格且内容确实支持时才使用较强语气。

完成标准：标题和封面共同说明“这是给谁、解决什么”，且不泄露正文无法兑现的结果。

### 5. 编排多图脚本

默认生成 7—9 页图文脚本，每页只承担一个信息任务：

1. **封面：** 读者身份、问题和单一承诺；
2. **代入：** 一个具体场景、失败或错误信号；
3. **误区：** 为什么常见做法不够；
4. **核心判断：** 真正需要改变的对象；
5. **方法步骤一：** 动作、判断条件和示例；
6. **方法步骤二或实测：** 真实材料、前后对比或截图；
7. **边界：** 不适用情况、风险或尚未解决的问题；
8. **总结：** 一张可保存的流程、清单或判断框架；
9. **互动：** 一个具体、容易回答且与下一篇有关的问题。

不同内容类型可替换结构：

- 教程型：问题 → 错法 → 原理 → 步骤 → 示例 → 清单；
- 复盘型：失败 → 原因 → 修改 → 结果 → 教训 → 下一步；
- 观点型：常见观点 → 反例 → 证据 → 修正命题 → 适用边界；
- 工具型：真实任务 → 旧流程成本 → 工具介入点 → 实测 → 失败项 → 适用人群；
- 构建公开型：真实问题 → 设计约束 → 当前版本 → 验证反馈 → 下个迭代。

每页同时给出：页面标题、正文要点、建议视觉和需要的证据素材。不要用大段缩小字号文字填满图片。

### 6. 写发布正文

正文承担三件事：

1. 补足图片中放不下的背景和边界；
2. 使用第一人称说明这套方法来自什么真实过程；
3. 自然放入搜索关键词和系列关系。

默认使用短段落、具体名词和动作。保留必要术语，但第一次出现时用一句读者语言解释。避免连续排比、过量 emoji、每段都总结、假装聊天和模板化感叹。

话题标签默认按以下结构选择 5—8 个：

- 2—3 个核心问题词；
- 2—3 个目标人群或场景词；
- 1 个学科或工具词；
- 1 个固定系列词。

不添加与内容无关的热门标签，不堆叠同义词。

### 7. 设计互动与关注理由

结尾不使用空泛的“欢迎交流”。生成一个能低成本回答的具体问题，例如：

- 你现在卡在检索、形成 idea，还是验证？
- 你更想看这个 Skill 的设计逻辑，还是一次真实使用过程？
- 这三种错误里，你最常遇到哪一种？

同时说明下一篇将继续解决什么，让关注理由来自系列推进，而不是请求关注。

可生成一条置顶评论，用于补充下载说明、勘误、来源、更新状态或收集下一轮问题。不得使用规避平台规则的外部导流暗语。

### 8. 可信度与风险检查

发布前逐项检查：

- 标题是否超出正文证据；
- 是否伪造论文、实验、下载量、身份、评价或用户反馈；
- 是否把相关性写成因果、把个例写成普遍规律；
- 是否遗漏会改变结论的前提和失败条件；
- 是否暴露未发表结果、合作方信息、学生隐私或内部代码；
- 是否大段复制论文、图表、课程或其他博主内容；
- 是否把 AI 生成内容冒充真实实验；
- 是否包含不必要的站外引流、联系方式或平台敏感表达；
- 是否留下可核对的来源说明和后续勘误方式。

发现风险时，优先删减、匿名化、改成示意例或延后发布，不用模糊化语言掩盖事实。

### 9. 依据发布数据迭代

用户提供后台数据时，先确认指标口径和观察窗口，再区分问题位置：

- 曝光低：选题需求、账号匹配、发布时间或初始分发仍不确定；
- 曝光有但打开弱：优先检查封面和标题是否不清楚或不可信；
- 打开有但完读弱：检查承诺兑现速度、页面密度和结构；
- 完读有但收藏弱：检查是否缺少可复用框架、步骤或总结页；
- 收藏高但关注弱：检查账号承诺、系列关系和下一篇是否不明确；
- 评论多但偏离主题：检查标题是否制造了错误争议或问题设置过宽。

这些是诊断假设，不是平台算法定律。每轮只改变一个主要变量，并记录：

```text
选题与目标 → 标题/封面 → 内容结构 → 发布结果 → 当前判断 → 下一轮单变量修改
```

完成标准：下一轮实验变量唯一，成功与失败都能提供信息。

## 默认账号路线：科研工作流型账号

当用户已有研究 Skill、代码仓库和真实科研项目，但没有明确账号定位时，优先建议：

> 用真实科研问题展示“一个模糊卡点如何被检索、拆解、验证并沉淀成工作流”，而不是只发布工具清单或泛泛经验。

推荐内容比例：

- 60% 广泛科研痛点与可执行方法；
- 25% 构建公开、Skill 设计与真实实测；
- 15% 具体学科案例、失败复盘和个人科研日常。

建议固定系列：

- `把科研做成工作流`
- `我把科研踩坑写成 Skill`
- `一个创新点如何被证伪`
- `论文不是看懂，是一步步推出来`
- `真实科研失败复盘`

这只是冷启动默认值。已有数据时以真实受众反馈调整，不把比例当成平台规则。

## 输出结构

完整任务默认使用以下结构：

1. 当前理解与内容源审计
2. 选题角度卡
3. 传播潜力判断
4. 标题候选与封面候选
5. 多图脚本
6. 发布正文与话题
7. 评论区与系列承接
8. 事实、版权、保密与平台风险检查
9. 发布后记录字段或下一轮实验

用户只要求标题、选题或复盘时，可以缩短输出，但不能跳过事实与风险检查。

## 硬边界

- 不承诺爆款、固定流量、涨粉数量或算法奖励。
- 不伪造科研经历、论文、数据、引用、奖项、导师评价或用户反馈。
- 不协助论文代写、数据造假、虚假署名、绕过查重或其他学术不端。
- 不搬运或近似改写其他博主的完整笔记；只能提取可泛化结构。
- 不公开未获许可的论文全文、课程材料、付费资料、内部文档和个人隐私。
- 不使用无关热点、虚假焦虑、身份羞辱或过度社会比较诱导互动。
- 不提供规避平台审核、隐蔽导流或批量刷量方法。
